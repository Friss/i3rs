# Log browsing and output

Open **File → Log Browser** to index a folder and its subfolders. Folder shortcuts and the metadata/range index persist in the user's i3rs application configuration directory. Refresh checks log and sidecar size/modification signatures; deleted logs are removed. Indexing and data export run in background workers. Errors remain visible in the dialog. Symbolic-link subdirectories are not traversed. Discovery decodes lap/beacon channels only when necessary; ordinary channel arrays remain lazy.

Search accepts whitespace-separated terms across filename, driver, venue, vehicle, event, date/time and range names. Expand a recording to inspect its details, custom fields and typed/trusted range hierarchy. **Main** opens the recording and selects that range; **Overlay** adds that recording/range to the shared comparison model. Existing unsaved recording analysis takes precedence over cached index details.

**File → Export Data / Split Log** selects Main or a particular Overlay. Full recording, selected range, Main zoom and custom recording-time bounds are distinct scopes. An unavailable selected range produces an error. Main zoom is not silently applied to another recording. Bounds are half-open `[start, end)`; the output grid starts at the exact selection start. Overlay output uses the source recording's clock and values, before visual alignment offsets/stretch.

CSV **Preview output** produces an immutable snapshot. Copy, export and printable HTML use that snapshot even if options subsequently change; generate another preview to use changed options. Data previews show the first 16,000 characters; printable result previews show up to 500 rows; saved files contain every row. Export has bounds of 10 million rows and 20 million cells to avoid unbounded allocations.

Cropped `.ld` output explicitly resamples. It does not claim to preserve mixed-rate native sample phases at an arbitrary off-grid origin. Its duration is `ceil((end-start)*rate)/rate`, with a possible final fractional sample period; its analysis ranges retain the exact requested end. Samples use unscaled engineering-unit f64 and retain the dedicated display precision without introducing f32 quantization. Nonzero scaling exponents on f64 prevented i2 Standard 1.1.4.457 from resolving continuous channels, so cropped output uses exponent zero. That legacy i2 version may round displayed values (for example 343.903 kPa to 344); the stored values and i3rs precision are retained. Old source sample spans are zeroed in the output copy before selected samples are appended. Sample-index sections and auto-generated GPS boundaries are cleared after a clock change; the geographic track definition remains available. Whole contained drag-run time-slip/reaction details survive; partial runs lose those elapsed-time claims. Original source files remain intact when exporting elsewhere.

Log replacement writes and syncs staged log/sidecar files, validates the encoded log by reopening it, and backs up all existing destination files before publishing. An ordinary publish failure rolls back files already published. Backup directories are named `i3rs-backup-<timestamp>` beside the output and contain numbered original files plus `RESTORE.txt` mapping each original filename. These backups also support manual recovery after a process/OS failure between the three file replacements. Reopen a source after write-back so the active memory map and recording identity reflect the replacement. Long details exceeding the binary field's UTF-8 capacity are rejected rather than silently truncated; complete custom details are carried in the analysis sidecar.

Reports, acceleration events, histograms and the existing calculation/scatter/mixture result tools offer **Copy CSV**, **Export CSV** and **Print / Preview** from the same results. **File → Print / Preview visible worksheet** captures the current visible worksheet, including charts. The snapshot can be copied as an image or saved as self-contained HTML. Open its **Print / Save PDF** control to use the browser/system print dialog. No physical print job is automatically submitted.

CLI automatic range discovery honors validated `.i3rs.json` analysis; explicit `--source ld` / `--source ldx` retain the selected format’s independent interpretation.

LDX sidecars use the i2 layer/marker-block hierarchy, observed Stage start/end and Run start markers, refreshed result details and an explicitly named private JSON detail for generic ranges. Generic range times are seconds; typed MoTeC marker timestamps are microseconds. Complete names/identities, range kinds, trust and comments remain authoritative in `.i3rs.json`; i2 does not consume that custom analysis file.

The core API is separate from GUI selection: `output::OutputPlan`, `output::OutputSeries`, `series_csv`, `earth_kml`, `log_writer::encode_log`, `write_log`, `reference_lap::ReferenceLap`, and `log_index::LogIndex`. `encode_log` is a pure byte/analysis operation and validates recording identity before modifying output. `write_log` requires an `.ld` destination. The older `export_csv` remains the documented legacy nearest-neighbour API for compatibility; the GUI uses `series_csv`. MoTeC's documented API exclusions are not used to silently restrict GUI CSV results.

Device `.td1` encoding uses the observed v1 layout. The decoder/encoder reproduces the complete i2-generated Rally fixture byte for byte; spatial resampling uses i3rs corrected distance and does not claim identical i2 distance correction. Physical device acceptance has not been tested. See [TD1 format and policy](td1-reference-format.md). The Standard 1.1.4.457 Create Reference Lap dialog identifies its target as lap gain/loss prediction or Telemetry Monitor and saves `.td1`. See [W09 validation](testing/i3r-9-log-output-2026-10-17.md).
